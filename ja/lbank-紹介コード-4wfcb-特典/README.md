# LBank 紹介コード 4WFCB：対象取引手数料の最大20%軽減と複数取引の費用集計

**LBank 紹介コード 4WFCB** には、紹介元から**対象取引手数料の最大20%軽減**が案内されています。実際に適用される割合と対象範囲は、利用するアカウントの条件で確認してください。[LBankの紹介リンク](https://www.lbank.com/signup?icode=4WFCB)を検討した後、複数の取引を行った期間を振り返るなら、注文の件数だけでなく、実行された料金を集計する必要があります。本記事は、その集計を小さな項目から組み立てるための案内です。

## 集計する期間と目的を決める

一回の利用、数日間、または月末など、どこで区切るかを先に決めます。同じ期間の中で何を知りたいのかも明確にしましょう。支払った費用の総額を知るのか、紹介条件の適用を確認するのかによって、読む記録が少し異なります。

期間を決めずに目についた記録だけを集めると、軽減の大きい項目ばかりが残ることがあります。反対に、関連する調整を取りこぼすと、費用が過大に見えることもあります。都合のよい数字を選ぶのではなく、対象とする範囲を最初に定義します。

この範囲は、口座のすべての履歴である必要はありません。目的に関係する活動へ絞り、その限界を説明できれば十分です。扱う情報を小さくするほど、各項目がなぜ含まれているかを確認しやすくなります。

集計途中の数字を共有する場合は、途中経過であることも添えます。未確認項目を含む見積もりと、実際の記録で照合できた合計を同じ確度で説明しないようにすると、後の更新で混乱しにくくなります。

## 注文件数を料金の単位にしない

二つの期間で注文件数が同じでも、数量や実行結果が異なれば、料金の合計は変わり得ます。一件あたりの平均だけで比較すると、その違いが見えません。実際の記録にある対象料金を出発点にします。

LBankの公式資料では、注文の種類や板の厚みについて説明されています。これらは、希望した数量と実際の執行を区別するための参考になります。入力した注文の全量が、同じ条件で直ちに実行されたと推測しないでください。

未実行の指示が残っている場合は、実行済みの費用集計とは別に記します。費用の集計を終えたことと、口座内の注文がすべて終了したことは同じではありません。必要な操作の判断は、その時点の正しい状態を確認してから行います。

## 対象料金を金額で足し合わせる

仮の期間に、対象と確認できた料金が0.6単位、1.4単位、0.5単位あったとします。同じ単位なら合計は2.5単位です。全額に20%軽減が確認されていれば、軽減は0.5単位、残る料金は2単位になります。

これはLBankの実際の料金を示すものではありません。件数ではなく料金の実額から計算する方法を示す例です。各取引の金額や条件が違っても、対象料金を正しく識別できれば、合計の基礎を説明できます。

ただし、通貨や資産の単位が異なる数字は、そのまま足せません。共通の単位へ換算するなら時点と方法を明記します。元の数量を消さずに残すことで、換算価格による差と、特典による差を後から区別できます。

## 一部だけが対象なら集計も分ける

すべての活動が同じ紹介条件を受けるとは限りません。実際の条件で対象商品や料金区分を確認し、未確認の活動は別に置きます。一つの期間に含まれているという理由だけでは、共通の軽減割合を適用する根拠になりません。

仮に総料金が10単位で、対象と確認できる部分が7単位なら、20%による軽減は1.4単位です。対象外または未確認の3単位を加えて2単位の軽減とするには、その部分の適用も確認しなければなりません。

後から条件が明らかになった場合は、該当する項目を修正します。集計を一度で完成させるために不明点を有利な仮定で埋めるより、未確認部分を見える状態にしておく方が、信頼できる合計へ近づけます。

## 表示済みの軽減を重複して数えない

ある画面が最終料金を表示している場合、そこから同じ特典を再度差し引くと、費用を過小に見積もります。元の料金と調整が別々に記録される条件なら、その二つの対応を確認する必要があります。

表示方法は、最大割合の案内だけでは分かりません。「この数字は紹介条件の適用後か」という問いを先に解決しましょう。見た目の項目数が多いからといって、それぞれが独立した還元を表しているとは限りません。

期間の終わりに計算が合わない場合も、すぐに率の誤りだと決め付けないようにします。対象範囲、単位、対応期間、軽減前後の表示という順番で確認すれば、どこに説明が足りないかを特定しやすくなります。

## 価格の結果を紹介の合計へ入れない

取引の実行価格と、明示された手数料は別の要素です。注文時に見た価格との差を、紹介によって補われる金額として自動的に扱うことはできません。対象手数料の軽減は、実行価格を保証する条件ではありません。

仮に同じ数量の取得費用が予想より3単位高くなり、対象手数料で0.2単位の軽減が確認できたなら、二つの数字は分けて示します。0.2単位の軽減があるから、3単位の差がなくなったと説明することはできません。

LBankの板や注文に関する公式説明を読むことは、こうした違いを理解する助けになります。ただし、どの注文方法でも常に最良の結果になるという結論にはなりません。費用集計と、注文方法の適切さの評価は別に行います。

## 軽減額ではなく残額を予算と比べる

軽減額が前の期間より増えた場合、元の料金も増えていないかを確認します。仮に20%の条件が同じなら、元の料金が5単位から20単位に増えると、軽減は1単位から4単位へ増えますが、残額も4単位から16単位へ増えます。

この例では、特典の数字が大きくなっても支出は小さくなっていません。利用の目的に合う活動だったか、予算内だったかを別に考える必要があります。紹介の合計を増やすために取引回数や数量を増やさないようにしましょう。

活動が少ない期間に特典も小さければ、それは自然な結果かもしれません。使える割引があるから必ず活動を作る、という順番にしないことが重要です。予算の上限は、使い切るべき目標ではありません。

## 短い集計メモを次の期間へ引き継ぐ

最後に、対象期間、対象商品、料金の合計、確認できた割合、残額、未確認項目をまとめます。必要以上の個人情報を含めず、数字の意味を後から追える形にしましょう。大量の画面保存より、条件の説明が役立つことがあります。

問い合わせが必要な場合は、関連する実行記録と計算の前提を示します。4WFCBという紹介識別子の確認と、認証情報の共有は別の話です。公式窓口に必要な情報だけを提供し、口座の操作権限を第三者へ渡さないでください。

次回の利用目的や商品が変わるなら、対象範囲を再確認します。前回の割合を無条件に使い続けるのではなく、現在の活動に適用される条件を使います。こうして合計の作り方を残しておけば、最大値だけに依存しない費用比較ができます。

## よくある質問

### 注文件数が同じなら手数料も同じですか？

数量、実行結果、対象条件が違う可能性があります。件数だけでなく、実際の料金記録を確認してください。

### 4WFCBで実行価格も有利になりますか？

ここで案内されているのは対象取引手数料の軽減です。注文の実行価格を保証する条件は確認されていません。

### 全体の料金に20%を掛ければ集計できますか？

全額の対象性と実際の割合が確認できる場合に限ります。対象外や未確認の費目は分け、表示済みの軽減を二重に数えないようにします。
