## Think in execution events

A position can begin with one order or several. It can then be increased, partly reduced, and finally closed. Each actual execution has its own value and fee treatment. A position summary is convenient, but it may hide the individual events needed to understand a charge.

Bitget's [futures order-cost guide](https://www.bitget.com/asia/support/articles/12560603828198) describes transaction fees using executed trading value and the applicable rate, and distinguishes them from funding on relevant perpetual contracts. The product, settlement currency and account level matter. A single percentage taken from a promotional heading cannot describe all of those inputs.

Before estimating a referral saving, identify which of these events the offer covers. An eligible reduction in a transaction fee should not automatically be extended to funding, a withdrawal charge or a loss on the position. The documentation for the actual account arrangement is what establishes the scope.

## An exit value can differ from the entry value

Use a deliberately hypothetical example. Suppose a position is opened with an executed value of 7,500 USDT, and the assumed transaction-fee rate is 0.04%. The opening fee would be 3 USDT. If the closing execution later has a value of 7,800 USDT at that same assumed rate, its fee would be 3.12 USDT. Together, those transaction fees would total 6.12 USDT.

If a separately confirmed referral arrangement reduced both entire fees by 20%, the combined reduction would be 1.224 USDT before any platform rounding, leaving 4.896 USDT. These are illustrative assumptions, not a quotation of current Bitget rates or confirmation of TSAVINGS eligibility.

The example highlights two points. First, multiplying the opening fee by two would miss the different closing value. Second, the 20% applies to the eligible fee amount, not to the position's value or to all money committed to the account. Neither the original fee nor the reduction establishes whether the position made or lost money.

## Partial exits need their own lines

If a position closes in stages, keep the actual value and fee for each reduction. Do not allocate the opening fee repeatedly to every partial close and then add the original opening fee again. That would count the same cost more than once.

A straightforward personal record has an opening section, a section for any increases, and a section for reductions or the final close. Keep funding entries separately. The total should reconcile to the account history for the period you are examining, with clear treatment of any later referral credits.

Where a fee is recorded in an asset other than the currency used in your summary, retain the original asset amount. State the conversion basis if you convert it. Otherwise, changes in that asset's price can look like changes in the fee itself.

## Margin answers a different question

Margin is the amount supporting a position under the account's risk rules. It should not be substituted for executed position value in a fee calculation. The same position value can be associated with different margin arrangements, while the relevant fee still depends on the execution and its applicable rate.

Bitget's [initial-margin guide](https://www.bitget.com/support/articles/12560603881482) explains that order verification can involve margin, fees and a potential opening loss, with different formulas for different account and contract configurations. This is why an order confirmation can reserve more than a simplistic position-value-divided-by-leverage calculation suggests.

Read the actual order confirmation before treating a difference as an error. A referral offer does not remove the platform's margin requirements or protect a leveraged position from liquidation. Changing leverage can alter required margin and liquidation risk; it does not change the executed-value base used to calculate a fee on the same exposure.

## Keep funding out of a transaction-fee shortcut

For a perpetual position held through relevant settlement times, funding can add another series of entries. Use the contract's displayed schedule and actual history. Do not rely on a fixed interval copied from an example because schedules can vary by contract and conditions.

A useful estimate separates known transaction charges from uncertain future funding. You can state what has already been charged and identify the assumptions behind any projection. Avoid presenting a projected funding payment as a guaranteed cost or receipt.

The same discipline applies to a referral credit. Until the account's terms and records establish it, keep an estimated saving labeled as an estimate. This produces a clearer result than subtracting a headline maximum from every line in the account ledger.
