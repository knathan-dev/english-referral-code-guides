## Give the invitation a clear starting record

Use the supplied [Metric referral invitation](https://app.metric.xyz/r/carcosa) if you choose this referral route. Copy **carcosa** exactly. Before continuing, make sure the application and wallet connection are the ones you intended to use. A referral identifier should never require you to disclose a seed phrase or private key to the person sharing it.

Write down the date, the wallet's public address, and the offer wording visible to you. If there is a confirmation of the invitation, preserve that confirmation. If there is no confirmation, record the status as unconfirmed instead of converting a clicked link into evidence that the boost is active. A screenshot can be helpful, but remove balances and unrelated account details before sharing it with anyone.

This starting record makes later questions much more precise. “Was this wallet linked to carcosa before this activity?” is answerable in a way that “Where is my bonus?” often is not.

## Keep three separate sections in the journal

The first section is **activity**: the dates and transaction references for actions you had independently decided to perform. The second is **program accounting**: the relevant points period and the points shown for that period. The third is **economic results**: network charges, other direct costs, and the change in the value or composition of your assets.

These sections describe different things. A recorded transaction is evidence of an action, not proof that the program must award a particular number of points. A points allocation is evidence of a program entry, not proof of a cash payment. A larger wallet balance may come from a transfer you made rather than from income.

Metric's [points documentation](https://docs.metric.xyz/use-metric/points) describes automatic weekly points and eligible participation. Consult its current version for the relevant rules. Avoid assuming that all transactions, all wallets, or all types of activity receive identical treatment merely because they appear in the same application.

## Record normal activity without creating activity for the record

A participation journal should help you understand decisions you already consider worthwhile. It should not become a reason to send funds back and forth, increase a position, or repeat trades just to produce a larger activity count. More transactions can add costs while leaving reward eligibility unchanged.

For each entry, a short note is enough: what you intended to do, the transaction reference, the amount involved, and any direct fee. If you move assets between your own wallets, identify that movement as a transfer. If you add more capital, record the contribution separately so that it cannot later be mistaken for performance.

You do not need to publish this journal. Its main value is consistency. Use the same timezone and measurement unit throughout a reporting period, and retain the original amounts when converting values into another currency. That makes a later comparison possible without pretending the conversion rate was fixed.

## A points example with a deliberately limited conclusion

Suppose, purely for illustration, that a program assigns 800 eligible base points and applies a confirmed 10% boost to that entire amount. The additional allocation would be 80 points, giving 880 points in total. This is arithmetic for an assumed rule, not a statement that your wallet will receive those amounts.

The calculation establishes no dollar value. It also says nothing about a future token, a conversion ratio, a distribution date, or whether a particular activity qualifies. Those are separate questions requiring explicit program terms. Record an unknown as unknown; assigning an imagined token price to points makes the journal look more precise while making it less reliable.

## Review asset exposure independently

If you use Metric for trading or liquidity activity, your assets can change in value while points accumulate. A points offer does not insure the assets, eliminate transaction costs, or establish that a strategy is suitable for you. Keep your assessment of the underlying activity separate from the invitation decision.

For example, an increase in an asset's market price can raise the displayed portfolio value even when no reward has been paid. Conversely, additional points can coexist with a loss in the value of the assets involved. Recording both observations is more useful than combining them into a single “earnings” number.

Revisit the original reason for participating at each review. If that reason has changed, a possible points boost should not become the only reason to continue. There is no requirement to spend additional money simply because you have followed a referral link.

## Questions to settle before the next reporting period

**Does clicking the link prove that carcosa is attached?** No. Keep the application's actual confirmation, if one is available, and seek clarification through Metric's official support route when the status is unclear.

**Should two wallets be treated as one record?** Keep them separate unless current program rules expressly consolidate them. This prevents activity from one address being used to explain another address's points.

**Does a 10% points boost mean a 10% investment return?** No. It describes an increase in an eligible program measure under the applicable terms. It does not specify a return on money, a token price, or compensation for losses.

**What is the most useful thing to save?** The offer shown when you joined, the wallet involved, dated activity references, and the program entries for the relevant period. Together, those records support a clear question without inventing a missing entitlement.
