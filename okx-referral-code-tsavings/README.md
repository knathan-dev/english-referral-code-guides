## Draw a small account map

Start with a private note showing the main account, any subaccounts you use, and the external services that need information from each. Beside each service, write its purpose: reporting, order management, or another specific task. This is an organizational exercise, not a request to disclose the account details publicly.

OKX's [subaccounts and API FAQ](https://www.okx.com/en-gb/help/subaccounts-account-mode-and-api-connections-faq) describes subaccounts as linked accounts that can separate activities or strategies. It also distinguishes API permissions for reading, trading and withdrawals. Those capabilities should not be treated as an inseparable package.

The account map helps prevent a common misunderstanding. An external application can be connected correctly while the referral question remains unresolved. Equally, a correctly recorded referral does not establish that an application is connected to the intended account. Check each relationship on its own evidence.

If you select this invitation, use the supplied route and check **TSAVINGS** in the registration flow wherever the referral information is displayed. Keep a dated record of the offer that applies to you. Availability, covered products and conditions can depend on the account and region.

A referral is also separate from identity verification and product access. Completing one step does not automatically complete the others. Resolve an unclear account status before attempting to diagnose it through an external bot or reporting tool.

## Match access to the actual job

Suppose you want an application to summarize past fees once a week. Its initial job is to read relevant records. It does not need to place a trade merely to report a charge, and a referral provider does not need your API credentials to identify the invitation you intended to use.

Write down the minimum information required, then review the permissions offered by OKX and the application. Keep credentials private and provide them only through the intended authorized connection. A screenshot showing a connection problem should exclude secrets, passphrases and verification codes.

If the planned job later changes from reporting to automated orders, treat that as a new access decision. Review the account, permitted actions and limits before expanding access. The convenience of an already connected tool is not evidence that it should control more of the account.

## Check account mode separately from credentials

An API key can identify the intended account without making every product available through it. Account setup and the features supported by a particular application still matter. OKX's FAQ explains that account mode is configured through the platform, and that a main account without subaccounts can show a fixed main-account selection in the API setup form.

When a setup screen behaves differently from a tutorial, inspect the actual account state rather than inventing missing subaccounts to make the screen match. Tutorials can describe another region, account arrangement or interface version. Use the relevant official documentation and the account's own controls to understand the difference.

Keep a short change log if you modify a connection: date, intended account, purpose and the permissions selected. That record makes later troubleshooting easier without requiring you to retain a secret in an ordinary spreadsheet or document.

## A fee report needs the correct accounting basis

For a hypothetical reporting setup, imagine a main account with a manual strategy and a subaccount with a separate strategy. A report that combines their trading charges may be useful, but it cannot assume that every charge belongs to the same promotional calculation. Identify which account generated each entry and what the offer actually includes.

OKX's [spot fee guidance](https://www.okx.com/en-gb/help/what-are-the-new-trading-fees-for-eea-users) explains that a referral code does not replace the applicable fee schedule; a program rebate is governed separately. That page is region-scoped and explicitly tells readers to check applicability. Use it to understand the distinction, not to copy its displayed rates into an account elsewhere.

A report should therefore preserve the original charge and any separate eligible credit. Keep the source record for each. An unexplained difference between the report and the platform is a reason to review the data mapping, timing and offer terms before concluding that the referral failed.

## Practical questions

**Is TSAVINGS an API key or password?** No. It is the referral identifier in this guide. It does not authenticate an external application or authorize account access.

**Will a bot automatically receive the advertised maximum saving?** Do not assume so. The account's offer must establish eligible products and activity, including any treatment of API orders or subaccounts.

**Does a subaccount remove trading risk?** Separating records can improve organization, but it does not make a strategy profitable or eliminate losses.

**What should I do with an unused connection?** Review whether it still serves a purpose and use the platform's controls to revoke access that is no longer needed. Keep the invitation record separately; it does not require an active third-party connection.
